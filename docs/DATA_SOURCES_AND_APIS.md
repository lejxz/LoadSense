# Data Sources And API Citations

This file records the datasets, generated data, APIs, and license links used or supported by the current LoadSense prototype.

## Current Data Sources

- OpenStreetMap route geometry, used for Cebu route polylines in `data/cebu_osm_routes.geojson`; license: Open Database License (ODbL) through https://www.openstreetmap.org/copyright and https://opendatacommons.org/licenses/odbl/1-0/

- Overpass API, used by `tools/fetch_osm_routes.py` to fetch OpenStreetMap Cebu corridor and route geometry; public API documentation and usage guidance: https://dev.overpass-api.de/overpass-doc/en/preface/commons.html; underlying map data license: ODbL through https://www.openstreetmap.org/copyright

- SQLite demo database at `data/loadsense_demo.sqlite`, used to persist route records, telemetry logs, latest fleet state, alerts, incidents, feedback, and chatbot queries; project-generated local database, with OSM-derived route records subject to ODbL attribution obligations when redistributed.

- Cebu route GeoJSON at `data/cebu_osm_routes.geojson`, generated from OpenStreetMap/Overpass and used to seed Cebu jeepney/PUV routes; license: ODbL through https://www.openstreetmap.org/copyright

- Cebu Jeepneys route reference, used as a local route-code reference such as route 04L: https://cebujeepneys.weebly.com/04l.html; license shown on site: Creative Commons Attribution-NonCommercial 3.0 Unported, https://creativecommons.org/licenses/by-nc/3.0/

- Synthetic GPS and occupancy telemetry, generated by backend startup simulation in `backend/app/core/demo_simulator.py` and optional streams from `edge/mock_telemetry.py`; team-generated demo data with no external dataset license.

- Synthetic historical occupancy logs at `data/synthetic_occupancy_logs.csv`, generated by `data/generate_synthetic_history.py` for demo forecasting; team-generated demo data with no external dataset license.

- Edge line-crossing output at `data/edge_line_crossing_counts.csv`, generated by `edge/line_crossing_counter.py`; team-generated demo evidence with no external dataset license.

- Demand forecast artifact at `cloud/artifacts/demand_forecast.json`, generated by `cloud/train_demand_forecast.py`; team-generated model output derived from synthetic history.

## APIs And Services

- FastAPI backend API in `backend/app/main.py` and `backend/app/api/routes.py`, serving `/api/telemetry`, `/api/ws/telemetry`, `/api/fleet`, `/api/routes`, `/api/routes/import`, `/api/routes/{route}`, `/api/places`, `/api/suggestions`, `/api/alerts`, `/api/alerts/{alert_id}/ack`, `/api/alerts/{alert_id}/verify`, `/api/incidents`, `/api/database/status`, `/api/eta/{stop_id}`, `/api/demand`, `/api/chatbot`, `/api/config`, and `/api/operator-feedback`; project-created API with no external API license.

- Photon / Komoot geocoder API in `backend/app/core/transit.py`, used optionally for remote place search from OpenStreetMap-derived data; Photon software license: Apache 2.0 through https://github.com/komoot/photon/blob/master/LICENSE; OSM-derived data license: ODbL through https://www.openstreetmap.org/copyright; public server notes: https://github.com/komoot/photon

- Google Fonts API, used by `app/index.html`, `app/mobile.html`, and `app/operator.html` for Manrope and Sora web fonts; API documentation: https://developers.google.com/fonts/docs/getting_started; Google APIs terms: https://developers.google.com/terms

- OpenWeatherMap API, listed in the concept roadmap as a possible future ETA weather input but not required by the current offline demo; terms: https://openweathermap.org/terms

- External LLM API, listed as a possible future replacement for the deterministic boarding assistant but not required by the current demo; license and terms depend on the selected provider.

## Supported Imports

- GTFS route import support in `backend/app/api/routes.py`, allowing uploaded `.zip` GTFS feeds with `shapes.txt`; no GTFS dataset is bundled, so license depends on the uploaded feed provider.

- Manual GeoJSON/JSON/CSV route import support in `backend/app/api/routes.py`; license depends on the source file uploaded by the user.

## Project Runtime And Validation Files

- Docker Compose service at `docker-compose.yml`, used to run the LoadSense backend container locally; project-created configuration.

- Validation scripts under `tests/`, including health, API smoke, demo-state, and chatbot regression checks; project-created validation scripts.

- Browser UI files under `app/`, including `index.html`, `mobile.html`, `operator.html`, `js/`, and `styles.css`; project-created frontend files, with external font loading as noted above.
